# Research: Legacy macOS Input Method codebase map for modern Swift migration and dependency removal

**Date**: 2026-06-13T22:19:52+01:00
**Researcher**: Codex
**Git Commit**: 8253c07a228479f6a093831a92985b50d2ccf1fb
**Branch**: master
**Repository**: BSMInputMethod

## Research Question

Study this legacy macOS Input Method codebase. The user wants to migrate it to modern Swift and remove dependencies, except possibly using SQLite.swift as the database backend.

## Summary

The repository is a legacy Objective-C macOS input method application built as an Xcode workspace with CocoaPods. The runtime is centered on InputMethodKit: `main.m` starts an `IMKServer`, `BSMInputMethod-Info.plist` names `BSMInputMethodController` as the input method controller, and the controller handles keypad input, marked text, composition commits, paging, and candidate display.

The core input method model is compact:

- `BSMInputMethodController` receives key events and coordinates the client, buffer, engine, and candidate window.
- `BSMBuffer` stores raw numeric input, marker glyphs, selection mode, paging state, candidates, and the current composed string.
- `BSMEngine` opens bundled `bsm.db` read-only through FMDB and queries the `ime` table.
- `BSMMatch` represents a `(code, word)` candidate pair.
- `BSMCandidatesWindow`, `BSMCandidateViewItem`, and `BSMView` implement the candidate UI with nibs and JAListView.

The live dictionary is SQLite-backed today. `data/bsm.db` is copied into both app and test resources. The database is generated by Ruby scripts from `data/bsm_applet.dat`, `data/BIAU1.TXT`, and `data/extension.txt`.

There are no Swift files, Swift build settings, Swift bridging headers, or modern Swift package declarations in this checkout. The project currently depends on CocoaPods for runtime libraries `FMDB`, `CocoaLumberjack`, and `JAListView`, and test libraries `Specta`, `Expecta`, and `OCMock`.

### Runtime Controller and Composition Flow

`BSMInputMethodController` subclasses `IMKInputController` ([`BSMInputMethodController.h:14`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/BSMInputMethodController.h#L14)). Its initializer gets the shared candidate window from the app delegate and creates a `BSMBuffer` using the shared engine ([`BSMInputMethodController.m:24-31`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/BSMInputMethodController.m#L24)).

All explicit key handling lives in `inputText:key:modifiers:client:` ([`BSMInputMethodController.m:33-139`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/BSMInputMethodController.m#L33)). The controller handles keypad decimal, digits, multiply, minus, plus, enter, divide, equals, clear, and space. Unhandled input returns `NO`.

Current key behavior:

- Keypad decimal enters selection mode, or selects the first candidate if already in selection mode ([`BSMInputMethodController.m:36-46`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/BSMInputMethodController.m#L36)).
- Keypad digits and multiply append input while the buffer is shorter than six raw input characters; in selection mode, digits `1-9` choose a candidate index ([`BSMInputMethodController.m:48-89`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/BSMInputMethodController.m#L48)).
- Keypad minus deletes one buffered step ([`BSMInputMethodController.m:91-92`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/BSMInputMethodController.m#L91)).
- Keypad plus toggles display of candidate codes in the candidate window ([`BSMInputMethodController.m:94-102`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/BSMInputMethodController.m#L94)).
- Keypad enter and space select the first candidate when a composed string exists ([`BSMInputMethodController.m:104-112`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/BSMInputMethodController.m#L104)).
- Keypad divide and equals page forward/backward through candidates ([`BSMInputMethodController.m:114-130`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/BSMInputMethodController.m#L114)).
- Keypad clear clears the current input ([`BSMInputMethodController.m:132-134`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/BSMInputMethodController.m#L132)).

Composition uses marked text while typing. `appendBuffer:client:` stores the current client, appends to the buffer, updates marked text, and shows candidates ([`BSMInputMethodController.m:141-148`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/BSMInputMethodController.m#L141)). `updateMarkedText` writes the buffer marker to the client with raw-text highlighting ([`BSMInputMethodController.m:169-174`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/BSMInputMethodController.m#L169)). `commitComposition:` inserts the buffer's composed string into the client, resets the buffer, and hides the candidate window ([`BSMInputMethodController.m:202-217`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/BSMInputMethodController.m#L202)).

The controller includes a Terminal-specific branch in `commitComposition:` that defers `updateMarkedText` for Terminal clients unless the client class name is `IPMDServerClientWrapper` ([`BSMInputMethodController.m:205-211`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/BSMInputMethodController.m#L205)).

### Buffer State and Candidate Selection

`BSMBuffer` is the composition state machine. It stores an engine reference, raw `inputBuffer`, display `marker`, `selectionMode`, `currentPage`, and `numberOfPage` ([`BSMBuffer.h:24-38`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/Engine/BSMBuffer.h#L24)).

The buffer maps input characters to marker glyphs in its initializer. Examples include `1 -> 一`, `2 -> 丨`, `3 -> 丿`, `4 -> 丶`, `6 -> 𠄌`, `0 -> 囗`, plus `.` and `*` ([`BSMBuffer.m:26-35`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/Engine/BSMBuffer.m#L26)).

`appendBuffer:` appends the marker for every recognized input. When the input is `.`, it enables selection mode without extending the raw input buffer; otherwise it appends to `inputBuffer` and marks candidates dirty ([`BSMBuffer.m:108-124`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/Engine/BSMBuffer.m#L108)).

`deleteBackward` removes one marker. If the marker suffix is `.`, it exits selection mode. Otherwise it also deletes one composed character from the raw input buffer and marks candidates dirty ([`BSMBuffer.m:126-138`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/Engine/BSMBuffer.m#L126)).

Candidates are lazy. When `_needsUpdateCandidates` is set, `candidates` asks the engine for the total match count and current page, computes total pages, and stores the first candidate word as `_composedString` when candidates exist ([`BSMBuffer.m:140-164`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/Engine/BSMBuffer.m#L140)). `setSelectedIndex:` replaces `_composedString` with the selected candidate word in selection mode ([`BSMBuffer.m:52-61`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/Engine/BSMBuffer.m#L52)).

Paging is held inside the buffer. `nextPage` and `previousPage` update `currentPage`, mark candidates dirty, and wrap at the ends ([`BSMBuffer.m:63-95`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/Engine/BSMBuffer.m#L63)).

### Engine and SQLite Dictionary

`BSMEngine` owns an `FMDatabase` and `NSCache` ([`BSMEngine.h:12-15`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/Engine/BSMEngine.h#L12)). It opens `bsm.db` from the bundle in read-only mode and applies SQLite PRAGMAs during initialization ([`BSMEngine.m:36-52`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/Engine/BSMEngine.m#L36)).

The main lookup method is `match:page:itemsPerPage:` ([`BSMEngine.m:73-105`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/Engine/BSMEngine.m#L73)). It converts `*` to SQL `%`, appends a trailing `%`, computes a minimum code length, and queries the `ime` table. Wildcard searches order by code length and frequency; non-wildcard searches order by code length and minimum row id ([`BSMEngine.m:82-91`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/Engine/BSMEngine.m#L82)).

`numberOfMatchWithCode:` performs a grouped count over matching words and caches the result ([`BSMEngine.m:108-127`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/Engine/BSMEngine.m#L108)). `possibleNextCodeWithCode:` enumerates digit strings `0-9` and keeps only next codes that have at least one match ([`BSMEngine.m:129-141`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod/Engine/BSMEngine.m#L129)).

The current `ime` schema in `data/bsm.db` is:

```sql
CREATE TABLE `ime` (`id` integer NOT NULL PRIMARY KEY AUTOINCREMENT, `code` char(6), `word` char(1), `frequency` integer DEFAULT (6000));
CREATE INDEX `ime_code_index` ON `ime` (`code`);
CREATE INDEX `ime_frequency_index` ON `ime` (`frequency`);
```

`data/bsm.db` is referenced by the Xcode project as `data/bsm.db` ([`project.pbxproj:77`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod.xcodeproj/project.pbxproj#L77)) and included in both app and test resource phases ([`project.pbxproj:354-365`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/BSMInputMethod.xcodeproj/project.pbxproj#L354)).

### Data Generation Tooling

The runtime database can be generated by Ruby tooling. `Rakefile` defines `preprocess:convert`, which reads the word frequency table, creates a converter for `./data/bsm.db`, reads the applet data as `BIG5-HKSCS`, converts it to UTF-8, inserts matching `(code, word)` rows, and then inserts extension rows ([`Rakefile:38-66`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/Rakefile#L38)).

`tools/bsm_converter.rb` uses Sequel with SQLite, creates the `ime` table, and inserts `code`, `word`, and `frequency` values ([`tools/bsm_converter.rb:4-28`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/tools/bsm_converter.rb#L4)).

`tools/word_frequency.rb` reads the frequency file as BIG5, converts it to UTF-8, and builds a hash keyed by word with a default frequency of 6000 ([`tools/word_frequency.rb:3-31`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/tools/word_frequency.rb#L3)).

The README attributes `data/bsm_applet.dat` to the applet version of the input method and `data/BIAU1.TXT` to Taiwan Ministry of Education word frequency data ([`README.md:108-112`](https://github.com/siuying/BSMInputMethod/blob/8253c07a228479f6a093831a92985b50d2ccf1fb/README.md#L108)).

## Architecture Documentation

The current architecture is a small Objective-C InputMethodKit application with a database-backed candidate engine.

Input flow:

1. macOS loads the input method bundle using the plist connection and controller metadata.
2. `main.m` creates the `IMKServer`, loads the main nib, attaches the server to the app delegate, and runs the app.
3. InputMethodKit instantiates `BSMInputMethodController`.
4. The controller receives key events and stores a current IMK client.
5. The controller mutates `BSMBuffer`.
6. `BSMBuffer` lazily asks `BSMEngine` for candidates.
7. `BSMEngine` queries bundled SQLite data and returns `BSMMatch` objects.
8. The controller updates marked text and candidate window display.
9. Commit inserts `buffer.composedString` into the IMK client and resets state.

Resource flow:

1. `data/bsm_applet.dat`, `data/BIAU1.TXT`, and `data/extension.txt` are inputs to Ruby preprocessing.
2. `Rakefile` and `tools/*.rb` create `data/bsm.db`.
3. Xcode copies `data/bsm.db` into app and test bundles.
4. `BSMEngine` opens bundled `bsm.db` at runtime.

UI flow:

1. `MainMenu.xib` provides the app delegate and candidate window objects.
2. `BSMAppDelegate` exposes the candidate window to the controller.
3. `BSMInputMethodController` calls `updateCandidates:`, positions the candidate window near the client caret, and shows it.
4. `BSMCandidatesWindow` reloads JAListView rows.
5. `BSMCandidateViewItem` loads a nib-backed row for each candidate.
